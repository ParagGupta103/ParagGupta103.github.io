Stock Market Data Warehouse

Airflow pipelines that load stock price data into Snowflake and BigQuery, with dbt models and data-quality checks that stop bad rows before anything is published.

40%lower compute cost from optimized dbt models and data-quality checks

Architecture

  1. Source dataStock price data from upstream APIs
  2. AirflowSchedules the extract and load
  3. Snowflake · BigQueryRaw tables land in both warehouses
  4. dbt modelsTurn raw tables into clean, modeled tables
  5. dbt testsData-quality checks gate what gets published

What I built

  • Airflow pipelines that load stock price data into Snowflake and BigQuery.
  • dbt models over the raw tables, optimized to cut compute costs by 40%.
  • Data-quality checks that run before publishing, so bad data, such as null closing prices, fails the run instead of reaching dashboards.

Key decisions

  • One extract, two warehouses. A single Airflow pipeline loads the same raw data into Snowflake and BigQuery, so the dbt models work from identical inputs on either platform.
  • Make each run do less work. I tuned the dbt models so routine runs process less data, which, together with the checks, cut compute costs by 40%.
  • Test before you publish. Data-quality tests run after the models build. If one fails, publishing is skipped and dashboards keep the last good data instead of showing bad numbers.
